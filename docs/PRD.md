# 产品需求文档 (PRD)

## 1. 背景与问题

### 1.1 用户痛点

大学生面临的通知信息过载问题：

- 通知分散在学校官网、学院网站、教务处、公众号等多个渠道
- 重要截止时间（报名、比赛、选课）容易错过
- 通知内容长，关键信息（时间、地点、链接）需要自己提炼
- 没有统一的地方管理"我需要做什么"

### 1.2 现有方案的不足

- 学校官网只有通知列表，没有个性化提醒
- 班级群转发容易漏看、被刷屏
- 手动记待办容易遗忘

## 2. 目标用户

| 用户角色   | 典型场景                          | MVP 是否覆盖 |
| ---------- | --------------------------------- | ------------ |
| 在校本科生 | 想知道最近有哪些比赛/活动可以参加 | ✅           |
| 研究生     | 关注学术讲座、奖学金通知          | ✅           |
| 班委       | 需要转发通知给同学                | 后期         |
| 辅导员     | 需要确认通知触达情况              | 后期         |

## 3. 核心用户故事

### 故事 1：发现即将截止的报名

> 作为一名学生，我想看到"未来 7 天内截止的报名/活动清单"，这样我就不会错过重要截止时间。

**验收标准**：

- 系统自动从已抓取的通知中提取截止时间
- 按截止时间排序展示
- 即将截止（3 天内）的标红提醒

### 故事 2：结构化查看通知

> 作为一名学生，我想看到通知的关键信息（时间、地点、对象、链接）一目了然，而不是读完整篇通知。

**验收标准**：

- 每条通知展示结构化卡片：标题、类型、截止时间、地点、面向对象、报名链接
- 原文可折叠查看

### 故事 3：自然语言问答

> 作为一名学生，我想问"最近有哪些数学建模相关的通知？"，系统能基于已抓取的通知回答。

**验收标准**：

- 支持自然语言提问
- 回答基于已抓取的通知内容（RAG）
- 引用来源通知

### 故事 4：按兴趣筛选

> 作为一名学生，我只想看和我专业/兴趣相关的通知。

**验收标准**：

- 支持按通知类型筛选（竞赛、讲座、报名、行政）
- 支持关键词订阅

## 4. 功能清单

### 4.1 MVP（P0）

| 编号 | 功能       | 描述                                       | 优先级 |
| ---- | ---------- | ------------------------------------------ | ------ |
| F01  | 通知抓取   | 定时抓取配置的通知源网站                   | P0     |
| F02  | 结构化提取 | LLM 提取标题、类型、时间、地点、链接、对象 | P0     |
| F03  | 待办列表   | 按截止时间排序的待办清单                   | P0     |
| F04  | 通知详情   | 结构化卡片 + 原文                          | P0     |
| F05  | 智能问答   | RAG 问答，基于通知内容                     | P0     |
| F06  | 学校配置   | YAML 配置文件适配不同学校                  | P0     |

### 4.2 后期（P1/P2）

| 编号 | 功能       | 描述               | 优先级 |
| ---- | ---------- | ------------------ | ------ |
| F07  | 主动提醒   | 即将截止时主动推送 | P1     |
| F08  | 用户偏好   | 专业/兴趣订阅      | P1     |
| F09  | 多学校支持 | 一次配置多所学校   | P1     |
| F10  | 微信集成   | 公众号通知抓取     | P1     |
| F11  | 日历集成   | 导出到日历 App     | P2     |
| F12  | 多用户     | 账号系统、个人待办 | P2     |

## 5. 通知类型分类

| 类型   | 代码             | 示例                     |
| ------ | ---------------- | ------------------------ |
| 竞赛   | `competition`    | 数学建模、创新创业大赛   |
| 讲座   | `lecture`        | 学术报告、校友分享       |
| 报名   | `registration`   | 选课、培训报名、活动报名 |
| 奖学金 | `scholarship`    | 国奖、校奖申请           |
| 行政   | `administrative` | 放假、注册、缴费         |
| 招聘   | `recruitment`    | 校招、实习信息           |
| 其他   | `other`          | 不属于上述类型           |

## 6. 非功能需求

| 维度     | 要求                       |
| -------- | -------------------------- |
| 抓取频率 | 每小时一次（可配置）       |
| 响应时间 | 问答响应 < 10 秒           |
| 数据保留 | 通知保留 6 个月            |
| 并发     | MVP 单用户，后期支持多用户 |
| 部署     | 本地运行，Docker 可选      |

## 7. 约束

- 无 OpenAI 官方 API，使用 opencode-go 线上模型
- Embedding 使用本地模型（opencode-go 不支持 embedding）
- 需遵守学校网站的爬取频率，避免压力
- 通知内容版权归原作者所有，仅用于个人学习

## 8. 成功指标（MVP）

| 指标               | 目标               |
| ------------------ | ------------------ |
| 抓取成功率         | > 90%              |
| 结构化提取准确率   | > 80% 关键字段正确 |
| 问答相关性         | 主观评价 > 4/5     |
| 截止时间提取准确率 | > 85%              |
