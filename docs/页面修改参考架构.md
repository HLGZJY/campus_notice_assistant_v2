# 页面修改参考架构

> 前后端分离落地后的分层归属速查。改页面时遵循"只动所属层"的边界约定。

## 分层归属（当前）

```
frontend/views/*.vue    → 前端页面（Vue3 + Naive UI，7 路由）
frontend/src/api/*.ts   → 前端 API 客户端（endpoints/http/tasks/events + 契约 types/schema）
api/routes/*.py         → FastAPI 路由层（/api/v1，薄转发：校验 + 调 services + 序列化）
api/tasks/*.py          → 异步任务（manager 单 worker + workers 注册表）
services/*.py           → 后端业务层（编排引擎，返回 dict，统一 {"ok":bool,"error":...}）
storage/*.py            → 后端数据层（SQLite / Chroma / hybrid）
core/*.py + utils/*.py + crawler/*.py → 后端引擎层（LLM Agent / 计量 / 抓取）
config/store.py + schema.py → 后端配置层
scheduler.py            → 后端常驻服务进程（API lifespan 拉起，可 CLI 独立运行）
data/ + config/*.yaml + .env → 后端运行目录
crawl.py/extract.py/index.py/qa.py/todo.py → CLI 入口（保留，复用同一 services）
```

## 页面 → 后端调用链（示例）

```
首页      /               HomeView.vue      → GET /notices/status-counts + /reminders/pending-count
通知浏览   /notices        NoticesView.vue   → GET /notices（分页）+ POST /tasks（crawl_all/extract_batch/批量）
系统配置   /config         ConfigView.vue    → GET/PUT /config/{models,providers,sources,crawl,extract} + POST /config/test-* + PUT /config/providers/{name}/api-key
智能问答   /qa             QaView.vue        → GET /qa/ask/stream（SSE）
订阅管理   /subscriptions  SubscriptionsView.vue → POST /subscriptions/preview + POST /subscriptions（202 任务）
服务市场   /market         MarketView.vue    → POST /events（service_button_click 埋点）
```

## 阶段 7 新增调用链

```
抓取按钮（NoticesView.vue）
  → POST /tasks {type: crawl_all, params: {sources?, mode?, max_pages?, deep_check?}}
  → api/tasks/workers.py:crawl_all → services/notice_service.py:crawl_all_sources(deep_check, mode, max_pages, sources)
  → sources 非空只抓选中来源（停用源始终跳过）→ crawler/web_crawler.py（增量早停 / 深检 / 并发 / 重试）→ storage/db.py（insert/update/log_crawl）

批量提取按钮（NoticesView.vue）
  → POST /notices/extract-preview（dry-run 预筛，不落库）
  → services/notice_service.py:extract_preview → _gather_extract_candidates（raw 排除已预筛 + failed 可重试）
  → 弹窗展示「将提取（可勾选）/ 跳过（带原因）」→ 确认提交 POST /tasks {type: extract_batch, params: {notice_ids, auto_index}}
  → workers.py:extract_batch → notice_service.extract_batch（notice_ids 命中即跳过预筛）→ 逐条调 LLM → update_extraction
  → 任务进度：manager progress_cb → tasks.progress（0~1）→ 前端按钮区 n-progress 实时条

省 Token 模式（skip_llm）
  → config.extract.skip_llm=true：extract_batch 不调 LLM，仅 match_notice + add_notice 索引，状态置 partial

配置「抓取与提取」tab（ConfigView.vue）
  → GET/PUT /config/crawl、/config/extract → config_service.update_crawl/update_extract → config/store.py 原子写
  → GET /config/sources（来源级策略字段）+ POST /config/test-source（suggested_pattern 自动填充 url_pattern）

配置「模型 / 供应商」tab（阶段 7.2 多模型候选 + .env 直写 / 阶段 7.3 卡片重设计）
  → models.<task> 为有序候选列表 {provider, models: [...]}：先尝试在前，失败自动切下一个（同供应商内）
  → 供应商卡片三重分区：基础（实例名 display_name + 类型徽章 type + Base URL + API Key + 状态点）/
     可用模型（下拉建议 MODEL_PRESETS ∪ 已添加，标签式） / 高级折叠（连通性测试·环境变量·只读标识）
  → ProviderConfig 新增 display_name/type：type 留空按 base_url 自动推断（local/bailian/opencode-zen/custom）；
    name 为只读唯一标识（任务引用它），改名走 YAML（消除旧 onNameBlur rekey bug）
  → PUT /config/providers/{name}/api-key → config_service.save_provider_api_key → ConfigStore.save_api_key
    （upsert 到 .env + 同步 os.environ 免重启生效；.env 已 gitignore，不落库）
  → 删除供应商二次确认（useDialog）+ 被任务模型引用时前置拒绝
  → LLM 失败切换判定：utils.llm.is_failover_worthy（400/401/403 不切；429/5xx/404/网络切）
  → 生效链路：core/extractor.py / qa.py / todo.py 按 get_model_candidates(task) 顺序构建 Agent 字典并切换
  → 连通性测试记账：POST /config/test-model 成功/失败均写 token_usage（task=test，取响应 usage 的
    prompt/completion tokens），供应商/模型随 provider 列一起入库

Token 用量 Tab（ConfigView.vue，「Token 用量」tab，阶段 7 遗留项落地）
  → GET /usage/tokens?days=N（默认 7，1–365，前端 7/30/90 切换）
  → api/routes/usage.py → services/usage_service.py:get_token_usage_summary（补 task_label，
    中文标签单一事实源在后端）→ storage/db.py:get_token_usage_summary（按 task×provider×model 分组）
  → 前端 useConfigStore.fetchTokenUsage(days) → n-statistic 汇总（调用/输入/输出/成功/失败）+ n-data-table 明细
  → task_label 与 provider 均来自后端（服务层 TASK_LABELS + 表 provider 列），前端不重复维护
```

## 约定

- 页面只 import 前端 api 客户端，不直连 storage/engine。
- 长耗时操作一律「提交任务 → 202 task_id → 轮询 GET /tasks/{id}」，页面用 `useTaskPoll`。
- 新增页面 = 前端加路由 + 后端加路由模块（`include_router(prefix="/api/v1")`）+ 更新 openapi.json 契约。
- 契约文件（openapi.json）是前后端唯一对齐点，改后端先导出契约再改前端类型。
