# 模块 1.5 Tool Calling 循环演练 — 完整实施计划

## 1. 交付物

- 新建根级独立脚本 **`tool_call_drill.py`**（对齐 `qa.py`/`test_token_usage.py` 的根级脚本约定）。
- **默认开启落盘**：每轮运行写 `data/logs/tool_call_drill_<YYYYmmdd_HHMMSS>.json`（沿用 `scheduler.py` 的 `data/logs/` 约定），同时终端打印逐轮日志。
- 不触碰任何主线代码：不导入 `core/`、`services/`、`utils/`（仅只读调用 `get_model_for_task("qa")` 取模型配置），不写 token_usage、不写库、不改配置。纯演练脚本。

## 2. 技术方案（关键决策）

用 **SDK 自动循环 + `Runner.run(..., max_turns=5)` 硬守卫 + `AgentHooks` 逐轮日志 + 工具函数级去重守卫**。

依据（已核实 SDK 0.19.3）：

- `max_turns` 是「模型调用次数」硬上限，超限抛 `MaxTurnsExceeded`（`agents.exceptions`），catch 后优雅收尾。
- `AgentHooks` 提供 `on_llm_start`（开新轮）、`on_tool_start`/`on_tool_end`（经 `ToolContext` 暴露 `tool_name`/`tool_arguments` 及返回结果），足以实现「每轮 tool_calls 日志回放」。
- **放弃手工拆轮 ReAct**：SDK 内部 `current_turn += 1` 在每次模型调用前，`max_turns=1` 会在工具执行后二次进入循环直接抛 `MaxTurnsExceeded`，无法干净「单轮单查」；且手工拆轮需自建 input_items 续跑，偏离「参考 `core/qa.py` 的 Runner 用法」。SDK 原生闭环更稳、更贴主线风格。

## 3. 各子任务实现要点

### 3.1 假工具 `query_mock_service(service_type)`（子任务 1）

- `@function_tool` 注册，docstring 写明入参枚举（`print`/`errand`/`photocopy`）与返回结构，不接真实服务。
- 返回硬编码 JSON 字符串：
  - 正常：`{"ok": true, "service_type": "...", "name": "...", "phone": "027-8888-xxxx", "hours": "8:00-22:00"}`
  - 不可用：`{"ok": false, "reason": "服务暂不可用，请稍后再试"}`
- 数据放模块级 `MOCK_SERVICES: dict[str, dict]`，供 `--scenario` 注入。

### 3.2 最大迭代守卫（子任务 2）

- `Runner.run(agent, prompt, max_turns=5)` 硬性封顶；catch `MaxTurnsExceeded`，输出「已达最大轮数」收尾。
- 自定义 `AgentHooks` 子类（挂到 `Agent.hooks`）打印逐轮日志：
  - `on_llm_start` → `[轮次 N]` 起始行；
  - `on_tool_start` → `  → tool_call: query_mock_service(service_type="...")`；
  - `on_tool_end` → `  ← 返回: <json>`（含 `[守卫拦截]` 标记）。
- 运行结束汇总每轮 `turn / tool_call_id / 工具名 / 参数 / 返回 / 是否守卫拦截` → 落盘 JSON。

### 3.3 tool_call_id 去重守卫（子任务 3）

- 工具函数内包**按本次 run 维度**的缓存：key = `(service_type)`，value = 上次返回。
- 命中缓存不重算，直接返回守卫消息：
  `{"ok": false, "guard": "duplicate_call", "message": "该工具同参数已调用过，结果与上次一致（已缓存）。请换用其他方式或参数，不要重复调用。"}`
- 每次 `run_drill()` 新建缓存实例，不同 prompt 互不串扰；日志标记 `[守卫拦截]`。

### 3.4 反瞎编（子任务 4）

- `instructions` 写入：只可使用工具返回数据；工具返回「不可用/无结果」时必须如实告知用户暂无结果；禁止编造电话/价格/营业时间；同参数被守卫拦截时换策略或如实回答。
- `--scenario unavailable` 将指定 service_type 标记为不可用，验证模型不编造。

### 3.5 CLI 设计

```
python tool_call_drill.py                              # 交互模式
python tool_call_drill.py "帮我找打印店电话"            # 单次提问
python tool_call_drill.py --scenario unavailable "帮我找打印店"
python tool_call_drill.py --scenario duplicate "帮我找打印店"
```

- `--scenario duplicate`：用「对同一工具同参数连续调用两次」的 trap prompt 确定性触发去重。
- 落盘默认开启，目录不存在时自动创建 `data/logs/`。

### 3.6 复用与隔离边界

- 复用：`get_model_for_task("qa")`（只读模型配置）；沿用 `core/qa.py` 的 client 初始化（`set_tracing_disabled(True)`、`AsyncOpenAI`、`set_default_openai_client`、`set_default_openai_api("chat_completions")`）。
- 隔离：直接调 `Runner.run`，不写库、不改配置；`if __name__ == "__main__"` 隔离副作用。
