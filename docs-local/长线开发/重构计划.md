## 阶段 7：前端（Vue 3 + Vite + Naive UI，与 1–6 并行）

> 并行机制：后端在 `api/`，前端在 `frontend/`，目录互不干扰；契约靠 OpenAPI 对齐（后端每完成一模块即 `/openapi.json` 可下载）。

- 脚手架：`npm create vite`（vue-ts）→ 引入 `naive-ui`、`vue-router`、`pinia`、`openapi-typescript`
- 契约同步：从 `/openapi.json` 生成 `src/api/types.ts`
- 页面平移（对应现有 6 页）：
  | 现有 Streamlit 页 | Vue 路由 |
  |---|---|
  | `app.py` 首页 | `/`（数据概览 + 待处理提醒红点） |
  | `pages/1_通知浏览.py` | `/notices` |
  | `pages/2_待办清单.py` | `/todos` |
  | `pages/3_智能问答.py` | `/qa`（SSE 流式渲染） |
  | `pages/4_系统配置.py` | `/config` |
  | `pages/5_订阅管理.py` | `/subscriptions`（两步式 → 确认弹窗） |
  | `pages/6_服务市场.py` | `/market`（假按钮占位） |
- 埋点：前端只发 `POST /api/v1/events`，逻辑留后端
- **commit-7**：`feat(web): Vue3+Naive UI 脚手架 + 6 页面平移，openapi-typescript 契约对齐`
- **验收**：`npm run build` 通过；后端挂载静态后手测全流程（浏览/待办/问答流式/订阅两步式/配置保存）

## 执行规则

- 每个步骤一个 commit，消息含对应 `feat(api|web|docs)` 前缀，与旧仓库 commit 风格一致
- 每步必须过验证再进入下一步；步骤 0 的引擎测试全绿是硬前置
- 后端/前端并行时，**契约文件（openapi.json）是唯一对齐点**，任一方向变更先更新契约再改代码
- 旧仓库 `legacy/main` 全程只读；需要查旧逻辑时 `git show legacy/main:<path>`，不回旧目录改
