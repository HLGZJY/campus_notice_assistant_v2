此路线适合所有后端工程师进阶，计算机环境就是这样：一直学习。去年还是清一色的分布式和微服务，今年已经变成一堆ai了，但本质上都是工程化的问题，所以如果还对ai有恐惧的话，可以试着了解一下这个。

## 一：AI应用工程师 / Agent 到底是什么？

### 工程定义

AI应用工程师 = 就是在传统后端的基础上接入LLM。
（这里面也会有并发，数据一致性，通信协议，本质上就是后端中的一种新型业务，很像传统的搜推工程）

Agent = 一个“能思考 + 能调用工具 + 能执行任务”的程序系统

### 本质拆解（核心四件套）

一个Agent =

1. 大脑 (LLM)
2. 手脚 (Tools / MCP)
3. 记忆 (Memory)
4. 规划 (Planning / Workflow)

后面的所有学习，本质都是在补这四个东西。

## 二：学习路线

### 阶段1：ai扫盲

#### LLM基础认知

你不用学算法，但必须知道：

- Token 是啥（影响成本）
- 上下文窗口（为什么会爆）
- 温度 / Top-p（控制风格）
- 幻觉（为什么会胡说）

Token 是什么？（为什么影响成本）
Token 是模型处理文本的最小单位——子词（subword），介于字符和完整词之间。用 BPE（字节对编码）算法把文本切分：

"Reinforcement learning optimizes long-term rewards." → ['Re', 'inforce', 'ment', ' learning ', ...]，"Reinforcement" 被切成 4 个 token（ch01-llm-architecture-and-optimization.md:57）
中文通常 1-2 个汉字≈1 token；词表规模 32K–128K（Llama-3 用 128K）
为什么影响成本：API 按 token 计费，且模型的注意力计算是 O(n²)。一本书 ~140K words ≈ 315K tokens——所以一次问答的成本正比于输入/输出的 token 总量。经验法则"每 token ≈4 字符"，但在代码/JSON/中文上可偏差 20-40%（ch18-agent-harness.md:18）。

上下文窗口（为什么会爆）
上下文窗口 = 模型一次能"看到"的 token 上限（如 8K/128K）。"爆"的本质是有限预算被历史、工具定义、RAG 内容、系统提示瓜分（ch18）：

C ≥ S(system) + M(memory/RAG) + T(tool defs) + H(history) + R(reserved output)
建议分配：系统 ≤10%、记忆/RAG ≤20%、工具 ≤10%、历史 ≤50%、预留输出 ≤10%（ch18-agent-harness.md:7）
历史对话无界增长，是爆窗口的头号原因 → 需要压缩/检索/截断策略
更深一层：Attention 内存是 O(n²)——128K 上下文的注意力矩阵就有 128K×128K=164 亿元素（FP32 需 64GB）。KV cache 逐 token 累积（每 token 约 40KB/GPU），这就是长上下文吃显存的原因（ch01:36, ch02:121）
两个隐藏坑：静默截断（API 超限时悄悄丢 token，模型丢了 system prompt 还在继续答）和 Context rot（上下文越长，模型准确率经验性下降）——所以要用 RLM 递归分解而非一味堆上下文（ch18:8,19）
温度 / Top-p（控制风格）
都是解码采样参数，控制"下一个 token 从多随机地选"：

参数 作用 取值建议
Temperature 缩放 logits 的平滑度。T→0 接近贪心（确定性）；T 高更随机 事实性任务 T≈0/贪心；创意任务 T≈0.7-1.0；RL 采样用 0.7-1.0（ch05:96）
Top-p 只从累积概率达到 p 的最小 token 集合里采样（自适应截断） p=0.9 是开放式任务默认（ch01:119）
书里的实例（ch01:133）：同一提示"Once upon a time,"——Greedy 给出泛泛的童话、T=1.0+top-p=0.9 给出创意意外输出、T=0.3 给出连贯常规输出。

关键：先定任务再选策略。 对齐训练的 RL 中，温度还决定采样多样性——GRPO 用温度 1.0 保证组内 G=8 条输出有差异（ch07:71），温度太低会 reward hack（重复输出）。

幻觉（为什么会胡说）
LLM 的本质是逐 token 预测下一个词的概率分布——它预测的是"最像语言的延续"，不是"查证事实"。幻觉的机制：

训练目标是似然而非真实：模型优化的是下一个 token 的交叉熵，学会的是文本模式，不是世界模型
解码放大：采样（高温度）或训练时扩长度时，模型在低概率区域"编造"
上下文不完整：静默截断丢了 system prompt → 基于残缺上下文幻觉且无错误信号（ch18:19）
受约束 ≠ 正确：受限解码保证输出语法合法（JSON 能解析），但"能解析的事实错误值"照旧产生（ch02:38）
书中给出的防御手段：

可靠检测需结合 RAG/外部核查——幻觉检测方法检测的是不确定性而非错误性（ch01:142）
事实性任务用 T≈0/贪心 解码；用 Contrastive Decoding 去除"泛泛信号"得到更精确输出（ch01:121,133）
把工具/检索输出当不可信数据而非指令，防 prompt injection 污染上下文（ch18:32）
对齐层：reward hacking 等训练期问题也要防御（ch09, ch27）
一句话：幻觉不是"bug"，是模型架构的固有产物——它是文本续写器，不是数据库。控制它靠任务适配的解码策略 + 外部知识（RAG/工具）+ 严格的上下文预算管理。

### 阶段4：Agent的Harness（核心）

Harness是围绕大模型搭建的一整套工程化系统，专门解决：
Agent 长时间运行稳定性、状态连续性、任务可靠性的问题。

业界公式：
**Agent = 模型 (Model) + Harness**

- 模型：负责思考、推理、决策
- Harness：负责稳定、不崩、不跑偏、可持续、可恢复

#### ReAct和PlanAct

一句话总结：ReAct是“边想边做”，PlanAct（Plan-and-Execute）是“先想好全盘，再一步步做”，是大模型Agent两大主流范式。

##### 一、ReAct（Reason + Act）：边想边做

2022年 Google + 普林斯顿论文提出。

###### (1) 核心流程（循环）

Thought → Action → Observation → Thought → … → 完成

- Thought（思考）：分析当前状态，决定下一步
- Action（行动）：调用工具/API
- Observation（观察）：拿到返回结果，进入下一轮思考

###### (2) 特点

- ✅ 动态自适应：每一步都根据最新结果调整策略
- ✅ 适合不确定/探索性任务：实时信息、多跳问答、环境多变
- ❌ 效率低、调用多：走一步看一步，容易绕圈、目标漂移

###### (3) 例子（查价）

1. Thought：要查iPhone 17价格，先找主流电商
2. Action：百度搜索“iPhone 17 电商价格”
3. Observation：返回京东、天猫、拼多多
4. Thought：逐个查这三家价格
5. ……循环直到对比完成

##### 二、PlanAct（Plan-and-Execute）：先规划，后执行

常简写为 P&E，也叫 PlanAct。

###### 1) 核心流程（两阶段）

阶段1：Plan（规划）→ 阶段2：Execute（执行）

- Planner：LLM 全局思考，输出完整步骤清单（Task List）
- Executor：按顺序逐条执行，中间一般不做大改
- （可选）Replan：失败时局部调整计划

###### 2) 特点

- ✅ 稳定、高效、可控：全局最优，步骤清晰，不易跑偏
- ✅ 适合结构化/长任务：报告生成、数据分析、固定流程SOP
- ❌ 灵活性差：前期规划错了，后面容易一路错到底

###### 3) 例子（查价）

1. Plan（一次性想完）
   - 步骤1：列出主流电商平台
   - 步骤2：在各平台搜索iPhone 17价格
   - 步骤3：对比价格，选出最低价
2. Execute（按步骤执行）
   - 执行步骤1 → 执行步骤2 → 执行步骤3 → 输出结果

##### 三、核心对比

| 维度      | ReAct                    | PlanAct（Plan-and-Execute）  |
| --------- | ------------------------ | ---------------------------- |
| 核心逻辑  | 边想边做，动态迭代       | 先全局规划，再顺序执行       |
| 时序      | 思考与行动交替           | 先一次性规划，后批量执行     |
| 灵活性    | 强（随时调整）           | 弱（计划定了难改）           |
| 稳定性    | 易漂移、绕圈             | 高、不易跑题                 |
| 效率/成本 | 调用多、成本高           | 调用少、成本低               |
| 最佳场景  | 实时信息、探索、环境多变 | 流程固定、长任务、结构化工作 |

##### 四、怎么选

- 不确定、要实时反馈、探索型 → ReAct
- 确定流程、长任务、要稳定高效 → PlanAct
- 工程常用混合：外层 Plan，内层 ReAct（大任务拆解，子任务动态处理）

##### 五、一句话总结

ReAct是“走一步看一步”，PlanAct是“先画好地图再赶路”。

# Agent记忆演进

## 1. 萌芽期（2022年前）：上下文窗口与简单记忆

- 核心：LLM仅依赖固定上下文窗口，无外部记忆，本质“无状态”。
- 代表：GPT-3、T5等原生模型；早期对话系统（简单历史拼接）。
- 局限：窗口有限、易遗忘、无长期积累、无法自我演化。

## 2. 起步期（2022–2023）：RAG与显式外部记忆

- 突破：引入检索增强（RAG）、向量数据库、长文本缓存。
- 关键论文：
  - Generative Agents (2023)：用自然语言日志 + 摘要做长期记忆，模拟人类行为。
  - MemGPT (2023)：虚拟上下文分层，类操作系统内存管理。
- 特点：显式文本/向量存储、可检索、但结构简单、无深度抽象。

## 3. 成长期（2024）：分类化、结构化与功能分化

- 方向：记忆分层（长短时）、分功能（事实/经验/工作）、结构化（图谱/层级）。
- 关键论文：
  - Reflexion (2024)：反思记忆，从失败中迭代优化。
  - Voyager (2024)：技能库记忆，持续学习动作策略。
  - A-MEM (2024)：卡片式关联记忆，支持记忆更新与推理。
- 特点：记忆可演化、可关联、支持自我改进、复杂度提升。

## 4. 爆发期（2025至今）：统一框架、三维体系与前沿融合

- 里程碑：《Memory in the Age of AI Agents: A Survey》（2025）
  - 提出 形态–功能–动力学（Forms–Functions–Dynamics）三维统一框架。
  - 覆盖200+论文，终结碎片化，建立领域标准体系。
- 前沿：生成式记忆、RL驱动记忆、多模态记忆、多智能体共享记忆、世界模型记忆。

### 纵向演进总结

- 存储：上下文窗口 → RAG / 向量库 → 分层/图谱/层级 → 三维统一架构。
- 能力：被动记录 → 检索 → 抽象/反思 → 自我演化/持续学习。
- 范式：静态 LLM → 带记忆 Agent → 自适应/成长型智能体。
